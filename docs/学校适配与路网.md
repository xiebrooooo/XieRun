# 学校适配与路网准备（自助版）

> 旧做法「一校一包」（每所学校编译一个专用 exe，把学校名 / 城市 / 路网编进程序）**已废弃**。
> 现在是一份**通用源码**：谁编译它、用谁的账号登录，它就按谁的学校运行 —— 学校信息不再
> 写死在代码里，不再需要为每所学校单独打包。
>
> 给 AI 的自助生成提示词见 [提示词.md](../提示词.md)。

---

## 1. 学校适配：不用改源码，程序自动识别

登录后，程序会自动检测当前校区的电子围栏 / 打卡点中心（见 `src/api/school_location.rs`），
把结果回填到「设备信息」页的城市与定位锚点（BD-09）：

- 自动检测失败时：「设备信息」页 →「自动检测学校位置」按钮，成功后记得点保存；
- 也可以手动填城市 + 锚点（纬度、经度）；
- 默认的「大连」配置**不允许用于跑步**（程序会直接拦下），必须换成自己学校的坐标。

跑步策略（距离上下限、可跑时段、必经点）不需要预先配置：程序运行时实时拉取，
学校改规则也不用重新编译。

## 2. 两种路线模式

| 模式 | 需要什么 | 说明 |
| --- | --- | --- |
| 经典打卡点环（`legacy`） | 只要账号 | 按打卡点自然生成环形轨迹，开箱即用 |
| 真实道路（`road`） | 一份该学校的 `.osm` 路网 | 轨迹贴着真实道路走，更自然 |

路网是唯一要自己准备的素材 —— 每所学校地形不同，没法通用。

## 3. 路网怎么来（三选一）

### a. 用账号历史记录生成（最省事）

在该校跑过步的账号，历史记录里带着真实道路的 GPS 轨迹：

```powershell
.\nekosportsworldtool.exe login --user <手机号> --pass <密码> --remember
.\nekosportsworldtool.exe records        # 确认是该学校账号
.\nekosportsworldtool.exe network-build --tracks <历史轨迹目录或文件> --out out\history-network.osm
```

产出 `out\history-network.osm`（WGS84），**只在本地生成、不会上传**。
可选参数：`--base-osm`（叠加到已有路网）、`--snap-m`（吸附半径，默认 8）、
`--include-date` / `--exclude-date`（按日期筛选轨迹）、`--report` / `--manifest`（输出报告）。

### b. 路网编辑器手绘

双击 `tools/road-network/路网编辑器.html`（Chrome / Edge）：

1. 「打开 .osm」载入现有路网（或从空白开始）；
2. 「载入打卡点」选 `points_cache.json`，打卡圈会落到正确位置；
3. 勾上「卫星」，对着高德卫星影像修路网（删边 / 连线 / 移点）；
4. 「保存 .osm」导出。

### c. 从公开 OSM 裁剪

能加载，但和真实打卡点不一定对齐，只适合「先让程序跑起来」的测试。

## 4. 路网怎么用

「路网」页 → 拖入或填写 `.osm` 路径 → 加载；跑步页切到「真实道路」模式即可。
程序把它记在 `config.json` 的 `osm_path` 里，下次直接用。

## 5. 已知坑

1. **坐标系**：osm 是 WGS84，打卡点是 BD-09（境内偏移几百米，随位置变化）。
   程序加载路网时自动逐节点对齐（`align_network`），**不要**再手工平移；也不要把
   已对齐的路网再对齐一次（2026-10-16 事故的成因，回归测试见 `track::tests::submit_network_is_aligned_exactly_once`）。
2. **锚点写错**：整体路线会偏移。锚点就是学校中心，让程序自动检测即可。
3. **规则会变**：学校的可跑时段、距离上限可能随时调整 —— 程序运行时实时拉取，不用管。
4. **编译缓存坏了**：报 `can't find crate for icu_provider / yoke` 之类错误时，
   先 `cargo clean --release` 再重编。
5. **点位限流**：打卡点接口 5 分钟限 3 次，程序内置 300s 缓存，正常使用不会触发。
