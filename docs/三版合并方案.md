# 三个版本合成一个：现状、方案与进度（2026-10-17）

## 一、本机的三个「运动规划」是什么关系

| 版本 | 目录 | 定位 | 特点 |
| --- | --- | --- | --- |
| 主仓库（通用版） | 本仓库（`D:\运动世界`） | 一份源码，运行期自适应 | 无内置学校；登录后自动识别学校位置；含 AI 运动、自动更新、路网页、CLI `run-all` |
| 个人免卡版 | `NekoSportsWorldTool-个人免卡版-20261008` | 一校一包（内置学校 + 卡密/免卡） | 工作台皮肤、GUI 批量页、设置页、多账号会话、内置路网；每个学校一枚 exe |
| 湖南朋友版 | `湖南石油化工职业技术学院-源码` | 只适配湖南一所学校 | 路网内置、无 AI、无卡密；带 TLS / 路线修复 |

三者是同一套代码的分支：主仓库 vs 个人免卡版，54 个共同源文件里 37 个不同；
主仓库 vs 湖南版，36 个不同。差异集中在「学校数据 + 界面增强 + 卡密」，
协议层、轨迹生成、提交链路同源。

## 二、结论：能合成一个，而且「主仓库通用版」就是那个「一」

主仓库这一版已经完成**运行期自适应**：

- `builtin_network`（编译期内置学校）已删除，登录后由 `school_location` 自动识别学校位置；
- 打卡点按候选端点自适应（`position` 0 起修复已合入），不再依赖某校写死的点位形态；
- 路网在运行期从 `config.json` 的 `osm_path` 加载，不再编译进 exe。

所以**一个 exe 就能跑所有学校**，不需要每校单独打包。合并方向因此确定为：
**以主仓库为底座，把个人免卡版里值得保留的东西移植进来**，而不是把三个学校版硬拼。

## 四、现在就能用的「一个」

`dist\运动规划-通用版\运动规划-通用版.exe`（本次由本仓库主分支编译）

- **跑所有学校**：登录哪个账号，就按哪个学校自动识别位置与打卡点；
- 页面：跑步 / AI 运动 / 运动记录 / 数据 / 我的 / 设备信息 / 运行日志 / 路网 / 关于；
- 批量：命令行 `运动规划-通用版.exe run-all`（GUI 批量页移植后可点按钮）；
- 首次使用：双击 → 登录自己的账号 →「设备信息」页确认城市/锚点（点「自动检测学校位置」）→ 回「跑步」页开跑。
